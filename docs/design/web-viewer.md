# 桌面网页浏览器

2026-11-01 的原生化重构一并移除了桌面 WebViewer 和用户脚本。2026-11-19 用户要求恢复并将它们列为持续维护的桌面功能。

## 行为

- 首页、侧栏空标签和命令面板提供「打开网页浏览器」。命令 ID 为 `webviewer:open`。首页和命令面板使用右侧标签，侧栏空标签在所在侧打开。
- 网页地址支持 HTTP(S)，无协议地址补 HTTPS。内容区从前进、后退、刷新和地址栏开始。每个网页在侧边竖排标签栏中独立显示，悬停显示网页标题，点击切换，右键、中键或 Delete 关闭。网页请求的 HTTP(S) 新窗口在同侧创建标签。标签切换保留访客，关闭标签后销毁访客。布局保存地址和标题，重新加载应用后恢复当前地址。
- 设置中的「内置浏览器脚本」管理文件和 `.user.js` URL 导入、匹配、授权与更新。见 [用户脚本设计](browser-userscripts.md)。
- Android 保持原生笔记功能，笔记里的外部链接继续由操作系统处理。浏览器版应用及深链的产品边界见 [原生应用边界](native-only.md)。

## 隔离与所有权

主进程 `configureWebViewer` 持有网页访客的附加规则、独立 Chromium 会话、地址限制和弹窗路由。访客强制沙箱、上下文隔离、Web 安全和关闭 Node 集成。网页和脚本网络均经该会话，Shale 本地运行时端口经会话拦截。随包的专用 guest preload 只负责用户脚本，与应用主 frame 的 preload 各自打包。用户脚本 IPC 检查已登记的访客主 frame、文档 token 与已批准权限。

工作区继续以既有 sidebar tab store 持有标签身份与状态。WebViewer 组件负责挂载和销毁访客，网页导航使用访客自己的历史。窗口或标签切换时，Vault 内容仍由原有 DocumentSession 管理。

## 重构验收

保留首页与命令面板入口、侧栏网页浏览、文件/URL 导入、定期检查和权限审阅。移除任何一项须先取得用户明确同意。用 `node tests/desktop-webviewer.mjs <打包应用可执行文件>` 测试原生宿主。测试使用本地 HTTP 夹具、隔离 Vault 与真实调度定时器，验证导航、弹窗、导入、执行、自动更新及扩权候选。
